## 1. 背景与问题

dtc.lab 做 DTC / 品牌增长服务（提案、冷启动、增长资产）。日常有大量品牌侧线索：询盘、转介、活动名单、站内表单、历史客户。

现有痛点：

1. **名单脏**：重复、无邮箱、阶段混乱，触达前要人工清洗。
2. **触达无节拍**：想到才发，或一发就群发；没有「破冰 → 价值 → 催约 → 停损」的克制节奏。
3. **回复沉了**：邮件/WhatsApp 散落，有回复却没人改状态、停序列、推进对齐。
4. **与提案脱节**：谈拢了还要另开文档/agent，上下文丢失。
5. **对齐数虚**：阶段拨到「对齐中」不等于真约上会，周指标不可信。
6. **合规红线**：非官方 WhatsApp 冷加、社媒爬人会毁品牌与账号。

历史产品骨架来自外贸 SDR 模板；流程「进料 → 清洗 → 触达 → 回收」可保留，默认画像与体验必须服务增长销售签单最后一公里。

## 2. 目标用户与使用场景

### 2.1 主用户（必须满意）

**增长销售 / 客户成功（Kevin 及同角色同事）**

- 每天打开「今日」：该回、该跟、该停。
- 导入线索 → 草稿 → **点头才发**。
- 有回复 → 推进到 **已约对齐**（有时间）→ **一键唤醒提案作战官**。

### 2.2 次用户

**管理员**：开账号、隔离资产、配 SMTP / 官方 WhatsApp、看吞吐指标。

### 2.3 非用户

- 陌生人 WhatsApp 冷加灰产。
- 本期完整客服工单 / 营销套件买家。

### 2.4 典型一天

08:30 今日：待回 / 该跟 / 该停。  
08:40 回完一条，阶段仍跟进中。  
09:00 导入 CSV，去重报告，批量首封草稿。  
09:20 点头发热线索。  
11:00 主理人回复「下周可以聊」→ 序列停 → 今日置顶。  
11:05 点「登记已约」写入周三 15:00 + 会议链接 → 阶段=对齐中，计入本周「约到对齐」。  
11:06 点「交给提案作战」唤醒提案作战官并带上线索上下文。

## 3. 产品原则

1. **一件事**：线索 → **约上对齐** → 可提案成交。  
2. **信任是功能**：默认草稿；没点头不外发。  
3. **克制通道**：邮件为主；WhatsApp 仅官方 Cloud API，不做陌生人冷加。  
4. **回复优先于发送**。  
5. **约上才算赢**：进入周指标必须有可核验的「已约」记录（时间必填）。  
6. **提案 handoff 不断层**：brief 必须唤醒提案作战官，禁止「仅剪贴板」作为 MVP 唯一路径。  
7. **少即是多**；**多用户资产隔离**。

## 4. 成功指标

| 指标 | 操作定义 | 目标（上线后 4 周） |
|------|----------|-------------------|
| 干净可触达名单 | 有效邮箱或已开白 WA，且非勿联系 | 导入后 90%+ 可判定 |
| 有回复率 | 外发后 14 日内 ≥1 次真人入站回复的触达占比 | 相对基线可观测提升 |
| **约到对齐数 / 周** | 本周新建的 **AlignmentBooking** 条数（见 §6.1）：必须含 `scheduledAt`；阶段因此进入「对齐中」 | 销售周会主指标 |

**明确**：仅把阶段改成「对齐中」而 **没有** Booking 记录 → **不计入**「约到对齐数」。

非目标：页面数、打开率虚荣榜、功能清单长度。

## 5. 范围

### 5.1 In Scope（MVP）

**四屏**：今日｜人｜稿｜战场

**能力**

- 进料：CSV / 手建；去重（邮箱 → 电话 → 姓名+公司）。
- 清洗：阶段含 **对齐中（独立阶段，不用标签）**；ICP 客群词；轻量热温冷；停滞天数 **默认可改（默认 5）**。
- 触达：四意图模板；活动草稿 → 显式发送；限速；无 SMTP 则 dry-run。
- 序列：0/3/7/14 映射四意图；回复/勿联系暂停。
- **催约 → 约上落点（写死）**：催约意图发出后，人详情/战场提供主按钮 **「登记已约」**（必填开始时间；可选会议链接/备注）。**不做**日历 OAuth 作为 MVP 依赖。登记成功 = 创建 Booking + 阶段→对齐中 + 序列暂停。可在催约模板脚注提示销售「对方同意后点登记已约」。
- **提案 handoff（写死）**：在「已回复 / 对齐中」显示 **「交给提案作战」**：一键 **SendToAgent → 提案作战官**，消息内嵌结构化 brief（公司、品类、意向、最近对话摘要、预算信号、已约时间/链接）。剪贴板仅作 **附加** 便利，不得替代唤醒。
- 回收：统一收件箱；手动登记回复；官方 WA webhook。
- 账号隔离；设置品牌/ICP/WA；SMTP 环境变量只读展示。

### 5.2 Out of Scope

社媒爬取；非官方 WA；Listmonk/Postal/Chatwoot/n8n 拼装；完整工单；复杂 BANT 仪表盘；日历双向同步（Google/Outlook OAuth）；英文界面（v1 中文）。

## 6. 信息架构

```
User
 └─ Contact
 └─ AlignmentBooking   ← 新增：约到对齐的唯一真源
 └─ EmailTemplate / Campaign / Sequence…
 └─ Thread / Message
 └─ Setting（含 stalledDays 可配置，默认 5）
```

### 6.1 AlignmentBooking（已约对齐）

| 字段 | 要求 |
|------|------|
| contactId / userId | 必填 |
| scheduledAt | **必填**（会议开始时间） |
| meetingUrl | 可选 |
| note | 可选 |
| createdAt | 系统 |

规则：

- 创建 Booking → Contact.stage = `对齐中`；进行中序列 pause。  
- 取消 Booking（若做）→ 回 `跟进中`，并从当周指标剔除（或标记 cancelled 不计入）。  
- 周指标 = `scheduledAt` 或 `createdAt` 落在本周的 **未取消** Booking 数（产品默认用 **createdAt 落在本周** =「本周约到的场次」，在设置里写清）。

### 6.2 阶段状态机

`新线索` → `已触达` → `已回复` → `跟进中` → **`对齐中`**（须有 Booking）  
任意 → `勿联系`

允许手动把阶段拨到对齐中，但 UI 必须拦截并要求先完成「登记已约」，禁止空拨。

### 6.3 回复事件

写收件箱 → 阶段 ≥ 已回复 → 序列 paused → 今日·该回。

## 7. 功能需求（增量相对 v1.0 加粗）

### 7.1 今日

FR-T1–T6 同前。  
**FR-T7** 今日可露出「本周已约：N」小计数（点进 Booking 列表），不堆漏斗图。

### 7.2 人

FR-P1–P5 同前。  
**FR-P6 登记已约**：表单必填 `scheduledAt`；保存写 Booking。  
**FR-P7 建议下一句**：按阶段/意图生成可编辑草稿——输入上下文 = 最近 3 条消息 + 品类/意向 + 当前意图模板；MVP 可用模板插值 + 最近入站首句摘要，**禁止空白按钮**；不自动外发。  
**FR-P8 交给提案作战**：调用提案作战官并附 brief。  
**FR-P9 停滞天数**：读 Setting.stalledDays（默认 5），列表「该跟」使用该值。

### 7.3 稿

FR-C1–C5 同前。  
**FR-C6 催约模板** 正文或页脚固定一句操作提示：「对方口头/书面同意时间后，到线索页点『登记已约』」。

### 7.4 战场

FR-B1–B5 同前。  
**FR-B6** 线程页同样提供「登记已约」「交给提案作战」。

### 7.5 Brief 载荷（交给提案作战官）

固定字段块：

- company, contact name/title, 品类/ICP tags, productInterest  
- 最近对话摘要（最近 ≤5 条，标注方向）  
- BANT 勾选结果（若有）  
- AlignmentBooking.scheduledAt / meetingUrl（若有）  
- 深链回建联联系人 URL  

### 7.6 账号 / 运维

同 v1.0。

## 10. 验收标准（销售可点头）

1. 早上看今日即可排工。  
2. 脏 CSV 导入可解释进出。  
3. 未点开始发送 → 零外发。  
4. 模拟回复后：阶段、序列、今日该回一致。  
5. **不能**无时间把阶段拨到对齐中；登记已约后本周「约到对齐」+1。  
6. **交给提案作战** 后提案作战官侧能收到含公司与对话摘要的 brief（可验证）。  
7. 两 USER 资产隔离；无外贸默认话术。  
8. 停滞天数可在设置修改并影响「该跟」。

### Booking 生命周期（PASS 备注，实现必遵）

- **改期**：更新同一条 Booking 的 `scheduledAt`（及可选 meetingUrl），**不**新建第二条，周指标不 +1。
- **取消**：`cancelledAt` 非空（或 status=cancelled）→ **不计入**周「约到对齐数」；联系人阶段回 `跟进中`。
- **手动补录回复**：IMAP 未配或漏收时，联系人/战场「手动登记回复」必须可用，并触发与入站相同的状态机（验收必测）。
